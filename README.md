# 打工人 · 工资账本（安卓 1.3.0）

按入职日期逐日累计固定工资，记录请假、加班、补贴、扣款、预支和实际发工资，并按主体及工资账期结算。支持安卓 8.0 及以上，本机离线记账。

## 1.3.0 升级

- 去除日历当天金额的白色底图，保留正数绿色、负数红色和零/未计薪灰色。
- 日历日期下方金额支持与其他金额相同的逐位滚动动效：从高位依次启动、至少三圈后准确落位；进入日历、切月及金额更新时展示。日期、农历与节日保持静态，负号和小数点固定，关闭动效后直接显示最终金额。
- 修复从“我的”页入职时长及记录分布图表区域横滑无法切换主页面的问题；日历切月、长名称横滚和表单手势保持原有归属。
- 在“我的 → 显示偏好 → 主题设置”新增四套风格：雾蓝经典、霓虹仪表、奶油手账、森林呼吸。分别采用经典卡片、仪表网格、票据手账与错落圆角布局，附独立主题预览。
- 冷启动页完全消失后，首页所有动态数据统一执行一次自检动效：按实际账本重新展示金额与统计数字滚动、进度图重播及轻微跳动；每次冷启动仅一次，返回前台不重复，关闭动效或系统减少动态效果时跳过。
- 首页自检的全部数字与图表动效完成后，“工资总览”卡片追加一次从左上到右下的强光扫过。等待真实动效完成后触发，返回前台不重播，关闭动效或系统减少动态效果时跳过。
- 所有图表的金额、百分比、笔数、工龄及周年进度数字共用逐位滚动，进入图表、切主题及数据变化时展示；日期与坐标轴刻度保持静态。
- 图表随主题采用环形/柱状、弧形仪表/双线、时间轴/日薪色块、轨道环/面积趋势等不同表现，使用实际账本数据；关闭界面动效或系统减少动态效果后静态显示。
- 主题仅保存在本设备，不随云端账本覆盖，重启后恢复；保留原计薪、记账、同步和清理逻辑。

- 首页、日历、明细、请假扣薪预览、逐日明细及导出共用计薪结果。一个自然月涉及两个工资周期时，日薪明细分别列出两个区间与天数。周期内调薪按各月份保存的工资标准分段折算。

## 坚果云双向同步

在“我的→坚果云同步”填写自己的服务地址、邮箱账号及第三方应用密码，不能填写坚果云登录密码。默认地址为 https://dav.jianguoyun.com/dav/ ，默认路径为“打工人/工资账本.json”。

首次保存连接后开启自动同步；升级已有配置时保留原自动同步开关。可在同步页开启。编辑停止约2.5秒后同步，应用前台每30秒检查远端；正在填写表单时等待保存或取消，联网恢复后补齐。应用关闭、系统停止进程或长期后台时不保证即时同步。

同步按共同版本对比到每条记录：不同新增自动合并，同一条修改或删除与修改相撞时先确认，只对冲突部分选择本机/网盘，保留其他新增。删除保留标记；上传使用强ETag和条件写入，遇到并发更新会重新读取合并，限流和网络失败退避重试。

清理默认仅作用于本机；勾选“同时清理云端对应记录”后，应用先读取两端账本并展示范围与数量，再以强ETag条件写入云端。未确认云端结果前不删除本机记录；中断后可核对清理状态再完成。仅清理本机时关闭自动同步，恢复前需要确认；两端一并清理保留原开关状态，未确认完成前暂缓同步。云端清理仅操作已配置的打工人账本，不删除网盘目录或其他文件。

网盘格式升级为 dagongren.webdav.v2，读取兼容旧v1；两台设备均需使用1.1或更新版本进行差异合并，1.0会拒绝读取新版网盘格式，避免旧逻辑覆盖新数据。首次两份账本都不同且缺少共同版本时，需要确认一次账本归属。

应用密码使用Android Keystore加密，仅保存在本机私有配置，不包含在账本或日志中。替换前快照保存在本机previous-book键；表格导出用于查账，不能直接导入恢复完整账本。未使用用户真实坚果云账号进行双手机联调，自动合并通过独立双设备模拟与HTTP测试验证。

## 联网日历

农历、节气离线覆盖2020—2040年；内置2020—2026放假调休资料。联网后从NateScarlet/holiday-cn读取年度安排，该项目自动每日抓取国务院公告，含公告原文链接；这是第三方整理数据，并非政府官方接口，无需本应用维护者逐年手动发布。

进入日历、启动和恢复前台时检查资料，常规检查间隔30分钟，恢复网络时补查。同时读取当前与下一年度文件，以处理下一年度公告影响上一年十二月的安排。原站失败时尝试同项目CDN，结果校验后缓存；空年、非法日期和非政府通知来源不采纳。网络失败继续显示离线或缓存资料，未取得安排的年份明确显示尚未收录。请求仅包含年份，不发送工资账本。

年度法定日仍按应用内年度规则与农历资料区分；通知中的连休/补班不会被误当作所有日期均为法定日。已保存请假扣款选择不随资料更新改变。政府法定计薪口径和本应用自然日记账口径不同，本应用不自动计算个税、社保或法定加班倍率。

日历联网来源：https://github.com/NateScarlet/holiday-cn ，MIT许可见 dist/holiday-cn-LICENSE.txt。原有农历及节气版权说明见 docs/calendar-sources.md 和包内使用说明。

## 构建和安装

网页逻辑使用Node.js 22及以上：运行 npm run check、npm run test:ui。安卓构建需要JDK17、Gradle8.11.1、Android SDK35。

1.2.3沿用1.0、1.1、1.2.0与1.2.1应用标识 com.tengzikeji.dagongren.upgrade 和固定测试签名，可覆盖1.0升级版、1.1、1.2.0、1.2.1与1.2.2并保留本机数据；0.9旧包仍需按原说明迁移。正式构建使用原固定签名以保证既有安装可升级，关闭调试；发行包并非应用商店上架审核。

工作流恢复并核对私有固定签名，若备份缺失必须停止构建，不能自行生成不同签名。签名产物保留90天，应另行保管离线备份。私钥不提交源码。

GitHub Actions执行逻辑测试、交互回归、HTTP单元测试、静态检查、编译和安卓15模拟器测试。安装包产物名为 dagongren-1.3.0-apk，附SHA-256校验文件。

主干通过全部检查后，发布工作流创建 v1.3.0 发行版并附签名 APK 与校验文件。发行包另存资料库以便手机获取。保留原分支历史；主干包含所有有效分支改动。
